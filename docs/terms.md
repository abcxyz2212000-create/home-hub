# 利用規約の確認記録

HouseHub が使う外部サービスについて、規約を読んで使い方と照らし合わせた記録です。

## 進め方（決まり）

- 新しいサービスを使う前と、今使っているサービスの使い方を変える前（定期実行・通知・外部への送信などを足すとき）に、規約の全文を読む。
- 実装前に出す仕様に「規約確認」の欄を入れる。読んだ規約の名前・版・日付、関係する条文、判断を書き、埋まるまで実装しない。
- 規約を読めないとき（ページを開けない、抜粋しかない）は、その時点で止まって依頼者に本文を頼む。推測では進めない。
- 確認した内容はこのファイルに書く。実在の氏名・メールアドレス・口座番号などは書かない。

- AUP 1.6（個人情報）：家族の利用者本人が、家計管理のために自分たちの情報を入れている。公開はしていない。問題なし。
- AUP 4.3（迷惑メッセージ）：通知は、本人が受け取りを選んだ家族の端末にだけ送る。問題なし。
- AUP 1.5（悪意を隠すための難読化）：通知の Edge Function は、1ファイルにまとめるために空白を詰めて置いている。悪意を隠す目的ではないので当たらないと判断。読める形での置き直しは依頼者の判断で行わない。
- AUP 3.4・4.4・5.1：暗号資産の採掘、攻撃の拠点にすること、盗んだカード情報の扱いなどは、どれにも当たらない。
- ToS 2(a)・2(c)：家族内部での利用だけで、第三者への提供や解析はしていない。問題なし。
- ToS 7(b)（payment cardholder information は事前の書面承認なしに保存不可）：カード台帳には、カード名・ブランド・番号の下4桁・有効期限（年月）・締め日・支払日・年会費がある。カード番号の全桁とセキュリティコードは保存しない。
  - 規約にこの言葉の定義はない。業界基準（PCI DSS）では、守るべきカード会員データの中心はカード番号の全桁、という理解のもとで「当たらない」と判断した。
  - 依頼者の判断で今のまま使う。カード番号の全桁とセキュリティコードは今後も保存しない。
- ToS 7(b)（HIPAA の対象となる医療情報）：保存しない。

## GitHub（コードの置き場）

- 2026-11 にアカウントが規約違反で停止された（再開の申請中）。
- 原因と考えているもの：GitHub Actions の定期実行（10分ごと）で家族への通知を送っていたこと。GitHub Actions の追加規約では、リポジトリのソフトウェア開発（作成・テスト・公開・デプロイなど）に関係しない使い方が制限されていると理解している。停止の理由は GitHub からまだ正式に確認できていない。
- 対応：通知の定期実行は Supabase（pg_cron と Edge Functions）に移し、GitHub Actions の定期実行は削除した。GitHub には、コードの保管と CI（テスト）だけを置く。
