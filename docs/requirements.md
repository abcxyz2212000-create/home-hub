# 家の管理ハブ 要件定義

最終更新: 2026-10-31
状態: **第1弾 実装済み**(2026-10-31 利用者から「実装OK」取得)。セットアップ手順は docs/setup.md

---

## 1. 目的・コンセプト

家の諸々(口座・カード・契約・書類/家電・ポイントカード/会員情報・在庫・家事・家計)を一元的に把握する。

**「一元管理」= すべてを1つのアプリ内で完結させることではない。**
このアプリは家のことの **入口(ハブ)** であり、それぞれ最適なツールに任せるものは任せて、リンクで行き来できればよい。

| 役割 | 担当 |
|---|---|
| 何がどこにあるか・いつ何が起きるかの把握 | **このアプリ**(台帳・予定・通知) |
| 家計の実績 | マネーフォワード(リンクで開く。公開APIは無い想定・未確認) |
| パスワード・暗証番号・カード番号全桁 | パスワード管理アプリ(**Google パスワードマネージャーを使用中**。アプリには「保管先」だけ記録) |
| 買い物 | Amazon(共通アカウント。リンクで開く。履歴の自動取得はしない) |
| 振込など口座の操作 | 各銀行のサイト/アプリ(リンクで開く) |

## 2. 利用者・利用環境

- 利用者: 2人(家族)
- アカウント: **1人ずつ個別のアカウント**(2026-11-01 変更。操作の履歴を人ごとに残し、将来のワークフロー機能に備えるため)。共通アカウントは管理者アカウントとして残し、管理作業(ユーザーの追加など)のときだけ使う
- 端末: PC とスマホの両方
- スマホ: **2人とも Android**。機種に依存しない作りが望ましい(難しければ Android 前提で可)
  - iPhone は未検証扱い(iPhone で通知を受けるには iOS 16.4 以降・ホーム画面追加が必要)
- 予算: **無料** 前提
- 既存アカウント: GitHub のみ
- Claude とアプリの連携は **要件外**(今は考えない)

## 3. 技術構成

| 項目 | 案 |
|---|---|
| アプリ形態 | Web アプリ(PWA)。PC・スマホ共通 |
| 公開 | GitHub Pages。**利用者合意済み**(無料・既存の GitHub アカウントで済む・HTTPS が自動で付く・push で自動反映。リポジトリは公開になる見込み) |
| データ・ログイン | Supabase(無料枠。GitHub アカウントで登録可)。**利用者合意済み** |
| 通知 | Web Push。毎朝の期限チェックは **GitHub Actions**(利用者決定。Node.js 標準機能のみで暗号化・送信) |

注意: Supabase 無料プランには一定期間アクセスが無いとプロジェクトが一時停止される制限がある(具体的条件は着手時に最新情報を確認)。毎日の期限チェックで実質回避できる想定。

- Supabase は一般に BaaS(Backend as a Service)と呼ばれる種類のサービス。画面(フロントエンド)は GitHub Pages、裏側(データ保存・ログイン・写真保管・定期処理)は Supabase が担当する
- リアルタイム反映(他の端末の変更が即時に画面へ反映される機能)は **使わない**。画面を開き直したときに最新データを読む

| データ | 想定 | 10年後の目安 |

| 第1弾 台帳 | 数百件 | 1 MB 未満 |
| 第2弾 在庫・買い物 | 品目200件、購入記録 年260件 | 約 5 MB |
| 第3弾 家事タスク | タスク30件を毎日完了(完了記録 年約11,000件) | 約 50〜100 MB |
| 第4弾 家計 | 集計は計算で出すため保存はほぼ無し | ほぼ 0 |

| 写真(保証書・レシート+在庫品目) | 家電50台×3枚+品目200件×1枚(圧縮後) | 約 70 MB(上限の 7%程度) |

## 4. セキュリティ方針

- パスワード・暗証番号・カード番号全桁は **アプリに保存しない**(決定)
- カード番号・会員番号は下4桁のみ
- **口座番号は全桁を保存する**(2026-11-01 利用者決定。Google ドライブの「口座マスタ」から移行し、同じ運用を引き継ぐため)。画面では伏せ字で表示し、押したときだけ30秒間表示する。CSV 書き出しとバックアップには含める(Supabase 無料プランに自動バックアップが無く、移行後はバックアップが唯一の控えになるため)
  - 移行後は Google ドライブ側のシートを削除する(置き場所を増やさない)
  - 暗証番号・ネットバンキングのログイン情報・カード番号の全桁は、引き続き保存しない
- 各アカウントには強力なパスワードを設定する(Google パスワードマネージャーで生成・管理)。データは Supabase の行レベルセキュリティ(RLS)で、ユーザーマスターに登録された有効な人以外から読めないようにする

### 4.1 認証(ログイン)
- 方式: **メールアドレス+パスワード**(1人1アカウント)。二段階認証・Google アカウントでのログインは使わない(二段階認証は将来検討)
- ログイン状態: **ログアウトするまで保つ**。端末を紛失したときはパスワードを変更して対応する
- **新規登録を無効にする**: アカウントは管理者が Supabase の画面で作る。他の人がアカウントを作れないようにする
- RLS は「ログインした人なら誰でも」ではなく、**ユーザーマスターで有効、かつメールアドレスが一致する人だけ** に許可する

### 4.2 ユーザーマスター・権限・操作の履歴(2026-11-01 追加)
- **ユーザーマスター**: 本名・**ニックネーム**(任意。2026-11-01 追加)・ログイン用メールアドレス(任意)・権限(管理者/一般)・有効/無効・メモ。メールアドレスが空の人は「ログインしない家族」(名義人などに使う)
- **権限**: 台帳の閲覧・追加・編集・削除、写真、CSV 書き出し、バックアップ、自分の端末の通知設定は全員。CSV 取り込み・ショートカットの設定・ユーザーマスターの編集・通知の鍵の作成は管理者のみ(CSV 取り込みとショートカットは画面での制限。ユーザーマスターと設定はデータベースでも制限)
- 有効でログインできる管理者が0人にならないようにする(画面とデータベースの両方で確認)
- **操作の履歴**: 台帳・写真・ユーザーマスターの追加・変更・削除をデータベースのトリガーで自動記録(誰が・いつ・どのデータの・どの項目を・変更前→変更後)。追記のみで、書き換え・削除はできない。保存期間は無期限
  - 口座番号の全桁は、履歴では伏せ字(`●●●1311`)で記録する
  - ログインせずに変更した場合(Supabase の SQL Editor やコネクタ)は「管理ツール」と記録する
  - 各データの詳細画面に「変更履歴」(新しい順に最大50件)と「作成した人」「最後に変更した人」を表示。全体の履歴画面は後回し
- 通知の端末には、どの人の端末かを記録する(将来、その人宛ての通知を送るため)
- 「このアカウントのすべての端末からログアウト」は、自分のアカウントだけに効く(他の人のログインは切れない)
- ページ(画面のプログラム)は誰でも開けるが、データはログインしないと取得できない
- GitHub Pages を無料で使うにはリポジトリの公開が必要な見込み(未確認)。公開されるのはプログラムと要件定義書のみで、台帳のデータは含まれない。プログラムには Supabase の公開用キーのみを入れ、秘密のキーは入れない
- 添付写真(保証書・レシート)は非公開のストレージに置き、ログインユーザーのみ閲覧可能にする(公開URLにしない)
- 写真にカード番号全桁などが写り込まないよう、添付画面に注意書きを出す

## 6. 第1弾の仕様案

### 6.1 全台帳に共通する項目
名称 / 名義人(**ユーザーマスターから選ぶ**。ログインしない家族も選べる。無効の人は「(無効)」と表示して残す) / 状態(利用中・解約済み) / 関連リンク(**複数登録可**。各リンクに「公式」「ログイン」「解約ページ」などのラベルを付ける) / パスワードの保管先(例:「Google パスワードマネージャーの○○」。自由入力) / メモ / タグ

### 6.2 台帳ごとの項目

| 台帳 | 主な項目 |
|---|---|
| 口座 | 金融機関名、**金融機関コード(4桁)**、支店、**支店番号(3桁)**、種別(普通/定期/証券/NISA など)、**口座番号(全桁。画面は伏せ字、下4桁は自動で作る)**、用途、マネーフォワード連携の有無 |
| カード | カード名、種別（クレジット/デビット/キャッシュ/プリペイド/その他）、ブランド、下4桁、有効期限(年月)、**引き落とし口座**(→口座)、締め日・支払日、年会費と発生月、家族カード/ETCの有無 |
| 契約・固定費 | 種類(光熱/通信/保険/サブスク/住居など)、金額と周期(月/年)、**支払方法**(→カード or 口座)、契約日、更新日、自動更新か、解約方法・連絡先、契約番号、書類の保管場所 |
| 書類・家電 | 品名、メーカー・型番、購入日・購入店、保証期限、説明書URL、保管場所、**写真添付(保証書・レシート)** |
| ポイントカード・会員情報 | サービス名・発行元、種類(ポイントカード/会員登録/アプリ会員など)、会員番号下4桁、登録メールアドレス、**紐づくカード**(→カード、任意)、ポイント有効期限(記録のみ・任意) |

#### 写真添付(書類・家電)
- 1項目に複数枚添付可。スマホのカメラ撮影・ギャラリー選択の両方に対応
- 保存容量を抑えるため、アップロード前にブラウザ側で縮小・圧縮する(外部ライブラリなし)
- 保存先は Supabase Storage(無料枠の容量上限は着手時に最新情報を確認。**未確認**)
- CSV 取り込み・書き出しの対象外(写真はアプリ上で個別に添付)。バックアップ(6.6)には含める
- 一覧では縮小版を表示し、開いたときだけ元の写真を読み込む(通信量の節約)

### 6.3 台帳どうしのつながり
- 口座画面: 「この口座から引き落とされているカード・契約」一覧
- カード画面: 「このカードで支払っている契約」「このカードに紐づくポイントカード・会員情報」一覧
- 目的: カード切り替えや口座解約時に影響範囲がすぐ分かる

### 6.4 ホーム画面
- 期限が近い予定
- 固定費の月額合計(年払いは月額換算)
- 外部サービスへのショートカット(マネーフォワード、Amazon、Google パスワードマネージャー、各銀行)。URL は設定画面で変更可能
- 最後のバックアップ(全データ書き出し)から1か月たつと、ホーム画面にお知らせを表示

### 6.5 通知(台帳の期限の前にスマホへ知らせる)
イベントごとに初期タイミングを持ち、項目ごとに変更可能。送信時刻は毎朝8時。

| イベント | 初期タイミング | 目的 |
|---|---|---|
| カード有効期限 | 1か月前 | 新カードの登録先を更新する |
| 契約の自動更新日 | 1か月前・1週間前 | 継続/解約の判断 |
| 年会費発生月 | 1か月前 | 継続/解約の判断 |
| 家電の保証期限 | 1か月前 | 期間内に修理依頼 |

- ポイントカード・会員情報の「ポイント有効期限」は **通知しない**(記録のみ)

### 6.6 データ移行
- 現在のスプレッドシートの形には合わせない。**このアプリの「あるべき項目」をベースに、利用者が後から情報を移す**
- そのため、台帳ごとのテンプレート(CSV/スプレッドシート。ポイントカード・会員情報を含む5台帳分)を用意し、取り込み機能を付ける
- バックアップ用に CSV 書き出しを付ける
- 金融機関コード・支店番号は、Excel が先頭の0を消した値(`36`)でも取り込めるよう、足りない桁を0で補う(`0036`)。桁数オーバー・数字以外はエラー
- 名義人は、ユーザーマスターの名前で指定する。登録されていない名前はエラー

### 6.7 バックアップ・使用量
- Supabase 無料プランには自動バックアップが無い(未確認)ため、**手動バックアップ**とする
- 設定画面に「全データを書き出す」ボタンを置き、全台帳の CSV と写真をまとめてダウンロードできるようにする
- 最後に書き出してから1か月たつと、ホーム画面でお知らせする
- 設定画面に現在の使用量(データベース容量・写真の容量)と無料枠に対する割合を表示する

## 7.1 実装時に決めた細部(第1弾)

- 外部ライブラリは使わない。Supabase との通信は fetch で直接行う(公式クライアントライブラリ不使用)
- 新規登録の無効化に加え、ユーザーマスター(members)で有効な人だけが読み書きできる RLS とした(当初は所有者テーブル app_owner の1アカウントのみ。2026-11-01 に置き換え)
- 端末紛失時のため「すべての端末からログアウト」ボタンを追加(パスワード変更だけでは、ログイン済みの端末が使い続けられる可能性があるため)
- 通知のタイミングは「何日前」で指定(初期設定: カード有効期限 30日前、契約の自動更新日 30日前・7日前、年会費 30日前、保証期限 30日前)。「なし」で通知しない
  - カード有効期限は「有効期限の月の末日」、年会費は「発生月の1日」を基準日とする
  - 1回の実行を逃しても翌日に送る。同じ段階の通知は1回だけ
- 入力内容にカード番号らしき数字(13〜19桁・Luhn 検査に合格)があると、保存前に確認を出す
- 「期限が近い予定」は30日前に過ぎたものから60日先までを表示
- 写真は長辺1600px・JPEG(一覧用の縮小版は長辺320px)に圧縮。1件につき20枚まで
- CSV は UTF-8(BOM付き)で書き出し。取り込みは UTF-8 と Excel の Shift_JIS の両方に対応。参照(引き落とし口座など)は名前で指定。エラーが1件でもあれば何も取り込まない
- 公開リポジトリの Actions ログに台帳の名前を出さない
- 運用中の「口座マスタ」(摘要・金融機関コード・支店番号・支店名・預金科目・口座番号・口座名義)との対応: 摘要→名称/金融機関名、支店名→支店、預金科目→種別、口座名義→名義人、口座番号→口座番号(全桁)。金融機関コード・支店番号は項目を追加
- 口座の CSV 取り込みは、口座マスタの見出し(摘要・支店名・預金科目・口座番号・口座名義)をそのまま受け付ける。見出しの上に表題の行があってもよい(上から5行以内で見出しを探す)。同じ項目の見出しが重複したらエラー
- 名義人はユーザーマスター(members テーブル)の ID で持つ。名前を変えると全台帳の表示に反映される(一時期の「家族の名前」の一覧と自由入力の名義人は、更新時にユーザーマスターへ移した)
- 既存の Supabase へは `supabase/schema.sql` の再実行で列が追加される(何度実行してもデータは消えない)

## 7.2 第3弾 家事タスク(2026-11-01 利用者決定)

目的: 従来のスプレッドシート(タスクリスト・マスタ・大掃除リスト)で行っていた「家事の負担を数字にして公平に分担する」ことをアプリに移し、担当者へ今日やることを知らせる。

- **表示名のルール**: ユーザーマスターに本名とニックネームを持つ。**名義人(全台帳)は本名**、それ以外(あいさつ・担当者・変更履歴の「誰が」・ユーザー一覧)は**ニックネーム**(空なら本名)。ニックネームは重複不可
  - 家族2人のニックネームは「しん」「はる」(本名はユーザーマスターにだけ登録し、公開リポジトリの文書には書かない)
- **家事の項目**: タスク名、カテゴリ(衣・食・住・事務)、グループ(企画・運用・保守)、サイクル(日・週・月・年・随時)、やる日、回数、1回の分数、調整係数(初期 1.0)、随時の点数、担当(ユーザー／全員／未定)、状態(利用中／停止)、メモ
- **やる日**: 週は曜日、月は日にち(無い日は月末)、年は月(その月の1日にお知らせ)。選んだ数が回数になる。やる日を決めない家事は回数を入力し、リマインドしない
- **負担の計算(従来の表と同じ)**: 月の時間 = 分 × 回数 × 換算(日30・週4・月1・年1/12) ÷ 60。点数 = 時間 × 1000 × 調整係数。随時は入力した点数 × 調整係数
- **分担の見える化**: 担当ごとの点数の棒グラフ、最多と最少の差、カテゴリ別の内訳表、時間/月。「全員」の家事は、担当のある家事を持つ人で等分。「未定」は別枠
- **今日の家事**: ホームと家事の画面に表示(自分の担当と全員の家事を先頭)
- **リマインド**: 毎朝の通知処理で、担当者の端末へ「今日の家事(N件)」を1日1通。全員の家事は全員へ、未定は送らない。ユーザーとつながっていない端末(ユーザーマスター導入前に登録した端末)には送らない(通知の設定をやり直すとつながる)
- **変更履歴**: 従来の「変更履歴」列の代わりに、操作の履歴で自動記録
- **作らないもの(今回)**: 実施の記録(予定と実績)、大掃除リスト、分担表の版の保存
- **移行**: 従来のスプレッドシートの「タスクリスト」シート(2024/2/17 版、34件)を登録。やる日は未設定で登録し、利用者が画面で設定する
- バックアップ(ZIP)に「家事.csv」を含める

## 7.3 共通口座への入金管理(2026-11-01 利用者決定)

目的: 従来のスプレッドシート「共通口座入金管理」(年ごとのシート、2022〜2025年)で行っていた、人ごとの「共通口座へ入れるべき額」と「未入金の残高」の管理をアプリに移す。

- **計算(従来の表と同じ)**: 月ごとに 合計 = 前月繰越 + その月の項目の合計、未入金(翌月へ繰越) = 合計 − 入金。項目はプラス=共通口座へ入れる額、マイナス=個人で払った共通の費用(入れる額から差し引く)
- **定例項目**: 人・費目・金額・開始月〜終了月。毎月自動で計上し、保存はしない(画面を開いたときに計算)。金額が変わるときは今の項目に終了月を入れ、新しい金額で追加する
- **臨時の費目(手入力)**: 月・人・費目・金額(±)・メモ。管理費・家賃更新料・立替・精算など。内訳表では「定例」と「臨時」をグループに分けて表示
- **入金**: 月・人・金額・メモ
- **画面**: 「お金の流れ」に「共通口座」タブ。人ごとの今月の額・入金済み・未入金の残高、月の内訳表(従来の表と同じ並び)、残高の推移の線グラフ、定例項目の一覧。ホームに本人の今月の額と未入金の残高
- **権限**: 有効なユーザーは誰でも記録できる。操作の履歴に記録。記録のあるユーザーは削除できない(無効にする)
- **通知**: 毎月25日以降に1回、本人の端末へ「今月 ○円/未入金の残高 ○円」。金額・名前は公開の実行ログに出さない
- **移行**: 2022〜2025年の全期間。基本・家賃・dアニを定例項目、それ以外の費目と入金を臨時の費目・入金として登録し、48か月すべての残高が従来の表と一致することを確認する。2026年は定例項目だけが自動で続き、入金などはアプリで記録する
- バックアップ(ZIP)に「共通口座_定例項目.csv」「共通口座_臨時の費目と入金.csv」を含める
